# Переход локального OpenCode fork на актуальный upstream

## Контекст

Текущая локальная ветка `dev` заметно разошлась с официальной веткой `anomalyco/opencode:dev`:

- в upstream есть 935 commits, которых нет в локальной ветке;
- в локальной ветке есть 16 commits, которых нет в upstream, включая 13 содержательных commits и 3 merge-коммита;
- пробное вычисление merge через `git merge-tree` предсказывает 14 конфликтующих файлов;
- часть конфликтов находится в `packages/app`, который upstream существенно переработал;
- несколько локально измененных файлов upstream переместил или удалил.

Обычное слияние upstream в текущую `dev` потребует вручную разрешать старые архитектурные конфликты. Более безопасный и понятный путь: взять актуальный upstream за новую основу, проверить его отдельно и выборочно перенести только те локальные возможности, которые остаются нужными.

## Цель

Перейти на актуальный upstream OpenCode без потери:

- сохраненных sessions и пользовательской конфигурации;
- необходимых локальных функций;
- возможности быстро вернуться на текущую рабочую сборку;
- ограничений build/test concurrency, защищающих VM от OOM.

## Что не делаем

- Не выполняем destructive rewrite текущей ветки `dev`.
- Не делаем `git reset --hard` и не заменяем текущую рабочую копию без rollback-ветки.
- Не переносим все локальные commits механически через `cherry-pick`.
- Не запускаем старую сборку на базе данных, которую уже необратимо обновила новая версия.
- Не меняем production-конфигурацию и service unit до завершения проверки новой сборки.
- Не отправляем commits и PR без отдельной явной команды пользователя.

## Результат задачи

После выполнения плана должны существовать:

1. Сохраненная ветка с текущей рабочей реализацией.
2. Новая ветка от актуального `anomalyco/opencode:dev`.
3. Минимальный набор адаптированных локальных commits поверх upstream.
4. Проверенная копия пользовательской базы данных и конфигурации.
5. Документированный сценарий обновления и rollback.
