# Диагностика памяти build, typecheck и tests

## Проблема

Во время разработки OpenCode сборка, typecheck и тесты могут резко увеличивать потребление RAM. 31 июля 2026 года на Debian 13 VM произошел системный OOM: ядро не смогло выделить память и принудительно завершило IntelliJ IDEA.

Нужно определить:

- какой процесс инициировал OOM и какой процесс был убит;
- почему monorepo-проверки создают высокий пик памяти;
- как связаны Turbo, `tsgo`, Bun tests, Vite и Playwright;
- какие ограничения параллелизма снизят риск без пропуска проверок;
- какая системная защита нужна при исчерпании RAM.

## Ограничения

- Не запускаем повторно полный build/typecheck/test только ради измерения: это может снова вызвать OOM.
- Не изменяем системную конфигурацию, swap, Git hooks или Turbo без отдельного решения пользователя.
- Используем kernel journal, текущие метрики системы и статический анализ scripts/configuration.

## Ожидаемый результат

- Подтвержденная причинно-следственная цепочка OOM.
- Разделение рисков typecheck, build и tests.
- Безопасные команды с ограниченной concurrency.
- План возможных изменений репозитория и VM для отдельного согласования.
