# Доставка SSE в несколько окон web-интерфейса

## Проблема

При двух одновременно открытых окнах web-интерфейса OpenCode одно окно обновляло состояние сессии по SSE, а второе могло не показывать поступающие изменения.

Web app использует глобальный endpoint:

```text
GET /global/event
```

Каждое browser window должно иметь независимое SSE-соединение и получать каждое опубликованное global event. Закрытие или reconnect одного окна не должны влиять на другое.

## Наблюдения

Runtime-логи подтвердили два одновременных подключения:

```text
2026-07-31 14:39:02 MSK: global event connected
2026-07-31 14:39:11 MSK: global event connected
```

Оба TCP-соединения оставались открытыми. `GlobalBus` использует Node `EventEmitter`, поэтому события рассылаются всем listeners и не распределяются между окнами как competing consumers.

Первое найденное окно потери находилось в моменте регистрации listener: `/global/event` создавал подписку лениво только после запуска response body stream и отправки `server.connected`. Событие, опубликованное в этом промежутке, могло быть потеряно конкретным новым окном. Исправление этого race прошло regression-тесты, но не устранило устойчивый пользовательский симптом.

Повторная диагностика показала клиентскую причину, специфичную для фонового окна. SSE reader периодически выполнял `await setTimeout(0)`, а доставка очереди событий в Solid state всегда планировалась через `setTimeout`. Browser throttling скрытого документа мог оставить TCP/SSE соединение открытым, но остановить чтение stream либо надолго задержать применение уже прочитанных событий.

## Почему Потеря Одного События Ломает Timeline

Во время stream ответа сначала приходит `message.part.updated`, создающий part, а затем серия `message.part.delta`.

Если новое окно пропустило `message.part.updated`, последующие delta для неизвестного part отбрасываются client reducer. В результате сервер продолжает отправлять события, но timeline этого окна визуально не обновляется.

## Требуемое Поведение

- Listener каждого `/global/event` соединения регистрируется до возврата streaming response.
- События между созданием response и началом чтения body сохраняются в per-connection queue.
- Два одновременных подписчика получают одно и то же опубликованное событие.
- Закрытие одной подписки удаляет только ее listener.
- Wire format SSE и API contract не изменяются.
- Скрытое окно использует `MessageChannel` task queue вместо throttled timers для чтения и coalesced flush SSE events.
- Видимое окно сохраняет batching и cooperative yield для отзывчивости UI.

## Вне Задачи

- Не добавляем durable SSE replay и `Last-Event-ID`.
- Не вводим shared worker или leader election между browser windows.
- Не изменяем client event coalescing.
- Не перезапускаем работающий OpenCode server автоматически.
