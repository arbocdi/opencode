# GPT-5.6 effective context cap for subscription accounts

## Контекст

OpenAI GPT-5.6 models в `models.dev` заявляют очень большой технический context window:

```text
context: 1_050_000 tokens
input:     922_000 tokens
output:    128_000 tokens
```

Для API billing это может быть корректно, но при использовании OpenAI через подписку/аккаунт в opencode фактическое автосжатие или доступный лимит оказывается заметно ниже. Наблюдаемое поведение: GPT-5.6 начинает требовать/провоцировать сжатие примерно около `370k` токенов, а UI при этом показывает слишком оптимистичный лимит около `1M`.

## Что делаем

Для прямого OpenAI provider и моделей семейства GPT-5.6 вводим локальный effective cap:

```text
openai/gpt-5.6*
usable context cap: 350_000 tokens
```

Это должно влиять на две вещи одновременно:

- индикатор контекста в UI должен считать максимумом примерно `350k`, а не `1.05M`;
- auto-compaction должен запускаться около `350k`, а не ждать catalog limit `922k`/`1.05M`.

## Что не делаем

- Не меняем `models.dev` cache и не правим upstream model metadata.
- Не меняем реальный OpenAI API model id.
- Не ограничиваем сторонние OpenAI-compatible providers, например Requesty/OpenRouter, потому что у них могут быть свои лимиты.
- Не добавляем пользовательскую настройку в config в рамках этого MVP.

## Почему cap именно 350k

Пользователь наблюдает автосжатие примерно около `370k`. Значение `350k` дает небольшой запас, чтобы opencode начал сжимать раньше фактического отказа/срабатывания внешнего лимита.
