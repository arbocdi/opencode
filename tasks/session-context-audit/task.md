# Аудит потребления контекста сессией 9945

## Контекст

В длинной сессии OpenCode с названием `9945` основная модель активно вызывает инструменты даже при использовании субагентов. Результаты чтения файлов, поиска, запуска команд и анализа логов сохраняются в истории и могут многократно попадать в последующие provider turns.

Текущий pruning умеет полностью заменять старый результат инструмента на marker, но не учитывает смысл результата и не создает краткое резюме. Нужно понять на реальных данных этой сессии:

- какие инструменты и конкретные типы результатов заняли основную часть активного контекста;
- были ли субагенты использованы недостаточно или основная модель повторно исследовала уже собранные данные;
- какие результаты можно удалять без потери качества;
- для каких результатов полезнее summary, ссылка на сохраненный полный результат или возможность загрузить его по требованию.

Исследование выполняется read-only. Содержимое пользовательских данных и секреты не копируются в отчет без необходимости; для анализа преимущественно используются размеры, типы, временная последовательность и обезличенные previews.

## Ожидаемый результат

- Количественная разбивка контекста по сообщениям, инструментам и категориям результатов.
- Причинно-следственная цепочка роста контекста.
- Оценка текущего pruning и compaction на фактической сессии.
- Практические рекомендации по использованию субагентов.
- Варианты реализации смыслового pruning: summary, сохранение полного результата вне prompt и повторная загрузка по требованию.

## Этап реализации после аудита

После обсуждения результатов политики инструментов реализуются отдельно по стабильным ID из `plan.md`. Пользователь явно выбрал `PROJ-1`: детерминированную проекцию исторических результатов `bash` и безопасную повторную загрузку по `callID`.

Остальные политики `PROJ-2`...`PROJ-8` не реализуются автоматически вместе с `PROJ-1`: для каждой нужен отдельный анализ фактического контракта и отдельная команда пользователя.

## Вне задачи

- Не изменяем исследуемую сессию и базу данных.
- Не включаем pruning в пользовательском конфиге автоматически.
- Не реализуем политики инструментов, которые пользователь еще не выбрал отдельным пунктом плана.
